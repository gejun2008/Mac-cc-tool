# 评测指标定义

这份文件定义**什么算对、怎么数、多少算达标**。工序(谁在什么时候做什么)见
[copilot-report-kit.md](copilot-report-kit.md),测评背景与泳道设计见
[eval-plan.md](eval-plan.md)。

> 红线:本文件只含口径,不含任何语料内容。明细表、汇总表、评估报告含语料,
> **只能存内网,不要提交进本仓库**。

## 两条铁律

**一、分母下沉到 unit 级。** 不要用「文档数」当分母。80 份文档只给你 80 个
样本,置信区间宽到无法下结论;同样这 80 份里有几千个数字 token、几百个列名,
标注工作量不变,区间窄一个量级。分母的单位是**列、数字、单元格、节点、边、
段落**,不是文档。

**二、不让模型算比例。** Copilot 只负责逐 unit 输出 0/1,百分比由 `SUM` 得到。
模型算比例会错,而且错了从结果上看不出来。「模型说准确率 92%」和「我数了
1,847 个数字,1,831 个对」在汇报场合完全不是一回事。

## 数据流与两张表

```
raw 文档 ──引擎──▶ 生成的 md          ← 被测对象
                       │
                    人工核对(照本文件口径)
                       ▼
                  ① 逐 unit 明细表     ← 原始数据,一 unit 一行,判定 0/1/NA
                       │  SUM + Wilson
                       ▼
                  ② 指标汇总表         ← 本文件的最终输出
                       │
                       ▼
                   评估报告.md         ← 结论与建议
```

### ① 逐 unit 明细表(输入)

| 字段 | 说明 |
| --- | --- |
| `case_id` | `<engine>-<doc_id>-<metric_key>-<三位序号>`,例 `layout-D017-NUM-01-003` |
| `doc_id` | 文档编号,不用文件名(可能含客户信息) |
| `doc_type` | word / ppt / pdf / xlsx |
| `stratum` | 分层标签,取自普查 `files.csv` 的 `stratum` 列 |
| `engine` | azure-layout / azure-read / mistral-ocr / ooxml / vlm-* |
| `metric_key` | 见下方指标定义表,必须原样填写 |
| `unit_id` | 人可定位的坐标,如「表3-列5」「第12个数字」「边 A→B」 |
| `src` | 原文片段,**逐字**,可截断不可改写 |
| `out` | 输出片段,**逐字**,可截断不可改写 |
| `judgement` | `1` 对 / `0` 错 / `NA` 该引擎无此能力 |
| `error_type` | 见错误码表;判定为 1 时留空 |
| `note` | 备注 |

### ② 指标汇总表(输出)

| 字段 | 说明 |
| --- | --- |
| `metric_key` | |
| `metric_name` | |
| `engine` | |
| `stratum` | 分层统计;另出一行 `stratum=ALL` 作总体 |
| `k` | 分子 = `judgement==1` 的行数 |
| `n` | 分母 = `judgement != NA` 的行数(**NA 不进分母**) |
| `value` | `k / n` |
| `ci_low` `ci_high` | Wilson 95% 区间 |
| `threshold` | 通过线 |
| `verdict` | 达标 / 未达标 / 样本不足 |

`n < 30` 一律记 `样本不足`,**不得写成百分比**,报告里写成
「n 例中出现 k 例」并列出 case_id。

### Wilson 区间

正态近似在 p 接近 1 时会给出越界的上限,一律用 Wilson:

```python
from math import sqrt

def wilson(k: int, n: int, z: float = 1.96) -> tuple[float, float]:
    """95% Wilson score interval. Returns (low, high)."""
    if n == 0:
        return (0.0, 0.0)
    p = k / n
    d = 1 + z * z / n
    center = (p + z * z / (2 * n)) / d
    half = z / d * sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return (max(0.0, center - half), min(1.0, center + half))
```

「越低越好」型指标(误合并率、幻觉率)同样用 Wilson,只是拿**上界**和通过线比。

## 指标定义表

`↑` 越高越好,`↓` 越低越好。

### 数字(金融红线)

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `NUM-01` | 数字逐位准确率 | 逐位完全一致的数字 token | 原文数字 token 总数 | ↑ |
| `NUM-02` | 负号保真率 | 负号正确保留 | 括号负数 / 尾随负号总数 | ↑ |
| `NUM-03` | 精度保真率 | 小数位未被截断 | 含小数的数字总数 | ↑ |
| `NUM-04` | 金融格式保真率 | 千分位、货币符号、± 、bp 完整保留 | 带格式的数字总数 | ↑ |

`NUM-01` 的 unit 是**每一个数字 token**,不是每一处差异。`1,234.50` 输出成
`1234.5` 记一次 0,同时命中 `NUM-03`、`NUM-04`,在三行里各记一次。

### 表格

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `TBL-01` | 表检出率 | 被识别为表格的表 | 原文表总数 | ↑ |
| `TBL-02` | 表头展平列名准确率 | 列名正确的列 | 总列数 | ↑ |
| `TBL-03` | 单元格内容准确率 | 内容一致的格 | 数据单元格总数 | ↑ |
| `TBL-04` | 跨页误合并率 | 误合并的表 | 跨页表总数 | ↓ |
| `TBL-05` | 跨页漏合并率 | 该合未合的表 | 跨页表总数 | ↓ |
| `TBL-06` | 表上下文关联率 | 表题 + 单位行 + 脚注随表保留 | 有上下文的表数 | ↑ |

`TBL-02` **单列统计,不并入 TBL-03**,否则会被正文格数稀释。

`TBL-06` 三者缺一即记 0 —— 「单位:人民币百万元」失联后,整张表的数字是废数据。

### 公式

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `FRM-01` | 独立公式检出率 | 检出 | 原文独立公式数 | ↑ |
| `FRM-02` | **行内**公式检出率 | 检出 | 原文行内公式数 | ↑ |
| `FRM-03` | 可渲染率 | KaTeX 渲染通过 | 检出公式数 | ↑ |
| `FRM-04` | 等价率 | 与原式数学等价 | 渲染通过数 | ↑ |
| `FRM-05` | 公式编号保留率 | 编号保留且正确 | 带编号公式数 | ↑ |

行内公式**必须与独立公式分开统计**。行内漏检是最大盲区 —— 整体看着没问题,
公式静悄悄变成了普通文字。

### 图片

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `FIG-01` | 图检出率 | 位置被检出的图 | 原文图总数 | ↑ |
| `FIG-02` | 图文位置正确率 | 插入在正确段落邻域 | 检出图数 | ↑ |
| `FIG-03` | **描述幻觉率** | 含原文不存在的数字或事实的描述 | 描述总数 | ↓ |
| `FIG-04` | 图内文字提取率 | 图内文字正确提取 | 含文字的图数 | ↑ |
| `FIG-05` | chart 数据还原准确率 | 正确数据点 | 数据点总数 | ↑ |

`FIG-03` 单列,**不与准确率类指标平均**。一个流畅但编造了「营收增长 23.7%」
的图描述,比不给描述更危险。

### 流程图

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `DIA-01R` | 节点召回 | 正确还原的节点 | 原图节点数 | ↑ |
| `DIA-01P` | 节点精确 | 正确的输出节点 | 输出节点数 | ↑ |
| `DIA-02R` | 边召回 | 正确的有向边 | 原图边数 | ↑ |
| `DIA-02P` | 边精确 | 正确的输出边 | 输出边数 | ↑ |
| `DIA-03` | mermaid 可渲染率 | 渲染通过 | 输出的 mermaid 块数 | ↑ |
| `DIA-04` | 分支条件文字正确率 | 条件文字正确 | 带条件的边数 | ↑ |

节点与边要**分别记召回和精确两行**,F1 在汇总层算:
`F1 = 2PR / (P + R)`。只记召回会让「多画了一堆边」的输出看起来很好。

**边的方向错,判定为 0**,不算部分正确。

### 阅读顺序与完整性

| key | 指标 | 分子 | 分母 | 方向 |
| --- | --- | --- | --- | --- |
| `ORD-01` | 段落错位率 | 顺序错误的段落 | 总段落数 | ↓ |
| `ORD-02` | 标题层级正确率 | 层级正确的标题 | 标题总数 | ↑ |
| `ORD-03` | 页眉页脚混入率 | 混入正文的页眉页脚 | 页数 | ↓ |
| `CMP-01` | 段落召回率 | 输出中出现的原文段落 | 原文段落数 | ↑ |
| `CMP-02` | 重复复读率 | 被重复输出的段落 | 原文段落数 | ↓ |
| `CMP-03` | 截断率 | 出现截断的文档 | 文档数 | ↓ |

`CMP-01/02/03` 的分母依赖**材料范围**。若核对时只给了关键页,这三项的分母
就只覆盖那几页,汇总表的 `note` 必须写明,报告的「已知局限」必须列出。

### 工程与可复现

| key | 指标 | 口径 | 方向 |
| --- | --- | --- | --- |
| `ENG-01` | 两次运行一致率 | 同文档跑两次,md 字节一致的文档数 / 文档数 | ↑ |
| `ENG-02` | 时延 | P50 / P95,秒/页 | ↓ |
| `ENG-03` | 成本 | 美元/千页,含 add-on | ↓ |
| `ENG-04` | 失败率 | 报错或空输出 / 文档数 | ↓ |

`ENG-01` 对生成式引擎(mistral-ocr、VLM)是必测项,确定性引擎恒为 1.0,
容易被整体忽略。不稳定的引擎无法做回归,这一条影响的是能否上生产,
不是准确率高低。

## 错误码表

`error_type` 只能取以下值,判定为 1 时留空:

| 码 | 含义 |
| --- | --- |
| `digit_wrong` | 数字被改写 |
| `sign_lost` | 负号丢失(括号负数、尾随负号) |
| `precision_truncated` | 小数位被截断 |
| `format_eaten` | 千分位 / 货币符号 / 上下标被吃 |
| `missing` | 未检出、漏失 |
| `duplicated` | 重复输出 |
| `truncated` | 输出截断 |
| `hallucination` | 原文不存在的内容 |
| `structure_broken` | 表格 / 层级结构崩坏 |
| `order_wrong` | 顺序错误(含边方向错) |
| `unrenderable` | LaTeX / mermaid 语法不可渲染 |
| `context_lost` | 表题 / 单位 / 脚注失联 |
| `insufficient_material` | 给定材料不足以判定 |

`insufficient_material` 的行**不计入分子也不计入分母**,单独统计其占比。
该比例偏高说明核对材料给得不够,不是引擎的问题。

## 通过线

| key | 通过线 | 依据 |
| --- | --- | --- |
| `NUM-01` | ≥ 99.9%,且**每一例错误逐条列出** | 金融红线,不适用统计容忍 |
| `NUM-02` `NUM-03` | 100% | 负号与精度丢失是静默且致命的 |
| `TBL-02` | ≥ 95%(**CI 下界**≥ 95%) | eval-plan 已定 |
| `TBL-04` | ≤ 2%(CI 上界) | eval-plan 已定 |
| `FRM-03` | ≥ 95% | 不可渲染等于没抽出来 |
| `FIG-03` | ≤ 5%,且「编造数字」类 = 0 | |
| `DIA-03` | ≥ 95% | 同 FRM-03 |
| `ENG-01` | 生产候选引擎须 ≥ 95% | 低于此无法做回归 |

其余指标**先不设线,只出数**。第一轮的目的是建立基线,过早设线会诱导
调参凑数。

判定必须用 CI 端点而非点估计:观测 96% 但下界 91%,不能报「达标」。

## 样本量

Wilson 95% 区间在观测值 95% 时的宽度:

| 分母 n | 95% 置信区间 | 可用性 |
| --- | --- | --- |
| 30 | 约 [81%, 99%] | 只能定性,不要写百分比 |
| 100 | 约 [89%, 98%] | 能区分「好」与「差」 |
| 300 | 约 [92%, 97%] | 能支撑立项结论 |
| 1000 | 约 [93.4%, 96.3%] | 能支撑通过线判定 |

要断言 `TBL-02 ≥ 95%`,需要 CI 下界越过 95%:n=300 时观测须达 98%
(下界 95.5%)。所以**列名的分母要凑到几百量级** —— 80 份文档里的表格通常
够,但要在抽样时确认,别测完才发现只有 60 个列名。

分层统计时**每层单独给区间**。只给总体会被占比大的简单层稀释:
简单层 99% × 70% + 困难层 80% × 30% = 93.3%,看着还行,而困难层已经不可用。

## 报告引用格式

正文里每个数字写成:

```
表头展平列名准确率 92.3% (1,187/1,286, 95%CI [90.7%, 93.6%], 42 份文档)
```

四个要素缺一不可:**值、分子/分母、区间、文档数**。附录里能按 `metric_key`
查到那 99 个错列名分别在哪个 `case_id`。做到这一点,报告不会被
「这个数怎么来的」问倒。
