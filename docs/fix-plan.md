| 2 | 数学公式失败 | 先确认 Azure DI 的 formula add-on 是否已启用(可能只是开关问题);docx 走 OMML → LaTeX 直读 | P0 | 待启动 | |

| 4 | 流程图无法结构化 | 解析形状与连接符,重建节点与方向,生成 mermaid 并校验可渲染 | P1 | 待启动 | |

| 6 | PDF 复杂表格错位 | 基于 DI 坐标重建表格拓扑,校验表头、列数与合并单元格 | P2 | 待启动 | |

## 排序说明

- **P0 先做,因为便宜**:问题 1 是数据被丢弃而非能力缺失,问题 2 可能只是
  付费开关没开。两项都应先查证,再决定要不要投开发。
- **静默失败优先于显式失败**:流程图没解析出来一眼可见;金融表格里数字被
  改写是无声的,危害更大,所以 1、3 排在 4、5 前面。
- **问题 6 最贵,放最后**,且要等语料格式普查确认 PDF 占比后再启动。

## 待确认

- 语料中 pdf / docx / pptx 各占多少(决定问题 6 是否启动);
- add-on 页费预算归属——**评估阶段不构成阻塞**:Layout 约 $10/千页,
  add-on(含 formula)再加约 $6/千页,80 份测试文档量级成本约十美元;
  仅在生产规模(十万页/月起)才需要立项审批。以官方定价页与本司 EA 折扣为准;
- MinerU 等开源方案暂不引入,待上述查证后再评估。
