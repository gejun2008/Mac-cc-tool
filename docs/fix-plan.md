# 不支持项修复计划表

针对能力评估中列出的六项「不支持」问题。周期为**单人人日估算**,验证方式
均为可判定的验收标准(达成即关闭,未达成不得进入下一项)。

## 排序原则

1. **先查开关,再造轮子**——引入新引擎前先确认现有服务的付费能力是否已启用。
2. **静默失败优先于显式失败**——流程图缺失一眼可见;数字被改写无声无息,危害更大。
3. **先测底数,不猜业务**——格式分布用普查得出,不靠估计。

## 决策门

| 触发条件 | 动作 |
| --- | --- |
| add-on 已启用但公式仍失败 | 公式转为自研项,MinerU 提前进入对照评估 |
| T0.1 显示 PDF 占比显著 | 启动 P5 |
| Office 占比 ≥30% | 阶段 1 的 OOXML 直读工具即可回本,按期推进 |
| PDF 占比高 **且** 公式密集 **且** 需生产吞吐 | 此时才提交 GPU 资源申请 |

## 明确不做 / 推迟

| 项 | 原因 | 替代方案 |
| --- | --- | --- |
| 全文双引擎复核 | 成本翻倍,收益集中在数字上 | 按单元格类型选择性触发(见 P6) |
| 字符白名单 | 金融符号种类多(¥ € ± 括号负数 千分位),易误伤,治标 | 数字级对账(见 P1) |
| MinerU 进主链路 | AGPL 许可 + GPU 部署两道坎 | 推迟至阶段 2,仅作 PDF 公式开源对照组;评估用 CPU 跑样本,不为此申请 GPU |
