# 不支持项修复计划

针对能力评估中列出的六项「不支持」问题制定。原则是**小步、可验证、先查后建**,
不追求一次性覆盖全部场景。

## 六项问题与归类

| # | 问题 | 归类 | 阶段 |
| --- | --- | --- | --- |
| 1 | Office 图片漏检 | 可能只需换输入形态 | 0 → 1 |
| 2 | OCR 错误无法发现 | 数据被丢弃,非能力缺失 | 0 |
| 3 | PDF 复杂表格错位 | 真工程 | 2 |
| 4 | 幻觉及字符噪声 | 部分可自动检测 | 1 → 2 |
| 5 | 数学公式失败 | 可能只是开关没开 | 0 → 1 |
| 6 | 流程图无法结构化 | 确定性工具可解 | 1 |

## 三条原则

1. **先查开关,再造轮子。** 引入任何新引擎(含开源)之前,先确认现有服务
   的付费能力是否已启用。公式一项很可能属于此类。
2. **静默失败优先于显式失败。** 流程图没解析出来一眼可见,不会流入下游;
   金融表格中数字被改写、列串位是无声的,后果严重得多。因此问题 2、4 的
   优先级高于 1、6。
3. **平台团队先测底数,不猜业务。** 语料的格式分布用普查得出,再带着数据
   与业务线确认优先级;能力边界矩阵本身就是交付物。

## 阶段 0 · 底数与开关调研(3–5 天,无外部依赖,不写新代码)

1. **文件类型普查**:统计语料中 pdf / docx / pptx / xlsx 的实际占比。

   ```powershell
   Get-ChildItem -Path $env:DOCEVAL_CORPUS_DIR -Recurse -File | Group-Object Extension | Sort-Object Count -Descending | Select-Object Count, Name
   ```

2. **Azure DI add-on 核实**:formula 等 add-on 是否已启用、计费方式、
   还有哪些开关未使用。纯查文档 + 核对自身调用参数,无需预算审批。
3. **保留原始 JSON**:确认当前是否只保存了 markdown 而丢弃了 DI 返回的
   坐标与置信度。若是,改调用代码留存 JSON——问题 2 有一半由此产生。
4. **`doceval scan` 摸底**:对 docx/pptx 跑普查,看 `native_structure` 分布,
   决定图与流程图走直读还是渲染。
5. **输入形态对比**:同一批 PPT/Word 转 PDF 后重跑 layout,对比图片与
   图形检出差异(转 PDF 会光栅化图形,使其对 OCR 可见)。

**产出**:一页《能力开关与底数报告》,并据此重新裁剪本 backlog。

## 阶段 1 · 确定性工具(约两周,并入 doceval,零第三方依赖)

按"不依赖格式分布"优先排序:

- **`doceval check`(L0 对账)**:以 OOXML 普查结果为客观参照,校验
  表格数量、行列数、数字 token 保全、md 表格竖线数一致性。无论 pdf 还是
  Office 占多数都有用,专治静默错误。→ 覆盖问题 2、4 的检测面。
- **OOXML 图片/图形提取**:带页码与坐标,结果可回链原图。→ 问题 1。
- **OMML → LaTeX**:Word 公式是结构化数学表达,转换确定性,准确率上限
  100%,并可自动生成公式真值,省去人工标注。→ 问题 5 的 docx 部分。
- **形状 + 连接符 → mermaid**:解析几何与连接端点重建图结构,输出后
  校验 mermaid 可渲染。→ 问题 6。

## 阶段 2 · 需要 POC 的两项

- **PDF 表格拓扑重建**:基于 DI 坐标重建行列与合并关系,校验表头、列数、
  合并单元格。泳道 A 后处理的核心,工作量最大。**触发条件**:阶段 0 普查
  显示 PDF 占比显著。
- **数值可信度门控**:置信度阈值 + **仅对数字单元格**做双引擎复核 +
  人工复核队列。→ 问题 4 的处置面。

## 明确不做 / 推迟

- **全文双引擎复核**:成本翻倍,收益集中在数字上,改为按单元格类型选择性触发。
- **字符白名单**:金融符号种类多(¥ € ± 括号负数 千分位),白名单易误伤,
  治标不治本;以数字级对账替代。
- **MinerU**:推迟至阶段 2,且仅作为 **PDF 公式**的开源对照组,不进主链路。
  评估阶段用 CPU 跑样本即可,**不因此申请 GPU**。

## 决策门

| 触发条件 | 动作 |
| --- | --- |
| add-on 已启用但公式仍失败 | 公式转为自研项,MinerU 提前进入对照评估 |
| 普查显示 PDF 占比显著 | 启动阶段 2 的 PDF 表格拓扑重建 |
| PDF 占比高 **且** 公式密集 **且** 需生产吞吐 | 此时才提交 GPU 资源申请 |
| Office 占比 ≥ 30% | 阶段 1 的 OOXML 直读工具即可回本,按期推进 |
